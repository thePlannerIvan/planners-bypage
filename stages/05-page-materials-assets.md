# 05 逐页材料包与图片处理

## 这一步在做什么

根据已经完成的内容展开，为每页回到真实来源准备必要材料和图片。材料包支持页面写作，不代替页面论证。

## 工作方式

只收集当前页面真正需要的材料，记录原文定位、用途、限制和缺口。已有资料足够时直接使用；出现局部缺口时，根据任务判断是否补充资料或素材；缺口会改变 Storyline 时，Proposal 交接路径回到 Proposal，独立运行路径回到 Stage 02 并向用户确认。

图片处理保持保守：保留原图，记录处理关系，并确认采用图片确实对应页面需要的对象、人物、事件或场景。不能用文件名、尺寸或像素检查替代内容判断。

## 不要做什么

- 不建立脱离页面任务的全库证据表。
- 不用泛化摘录代替与页面内容直接相关的材料。
- 不把材料包写成完整 By-page，也不把版式决定提前交给本阶段。

## 产物

- `.bypage-work/page-material-packs.json`
- 更新后的 `.bypage-work/asset-manifest.json`
- `.bypage-work/assets/original|processed|previews/`

现有脚本继续负责 Hash、来源引用、文件存在性和图片状态等机械检查。

## 完成标准

- 语义完成：每页能回到与当前内容任务直接相关的来源和图片；重要缺口已暴露。
- 机器检查：材料包覆盖页面，来源与 Asset ID 有效，文件和 Hash 正确。
- Validator 不能证明：材料是否已经形成有说服力的完整页面，这由 Stage 06 和人工审阅判断。
