# 02 一轮集中选择

## 这一步在做什么

把会改变 Storyline 的用户偏好一次敲定，避免固定问卷和多轮机械追问。

## 工作方式

先读取 `project-memory.md`和 Source Index，再给出当前理解与推荐。只展示材料没有唯一答案的项目；每项提供 2–3 个真实不同的选项、推荐及取舍，最后统一询问“还有没有其他意见需要补充”。

候选维度包括：

- 用途与受众；
- 演讲推进、独立阅读或混合；
- 忠实整理、编辑重组或深度重构；
- 页面密度与预计页数区间；
- 正文、附录、必须保留和明确排除范围。

材料已经明确的维度直接写为模型理解，不强迫用户点击。不同选择没有真实下游差异时不要制造选项。

## 人机介入

用户一次性选择并可输入自由意见。方向、范围和重要删改没有默认批准；界面可标注推荐，但不能替用户决定。

## 产物

将确认结果和选择理由写入 `.bypage-work/content-brief.md`。自然语言 Markdown 即可，不建立额外 JSON Contract。

## 完成标准

- 语义完成：受众、用途、改写边界、密度和内容范围足以约束 Storyline。
- 机器检查：文件存在即可；Validator 不能证明用户选择是否合理。
