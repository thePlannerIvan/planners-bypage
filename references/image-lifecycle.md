# 图片资产生命周期

## 发现与分类

先提取并登记原图，按语义分为：内容证据、叙事素材、品牌资产、参考素材、装饰噪声、待判断。重复 Logo、页眉页脚、小图标、背景碎片和整页缩略图通常不是内容图，但若它们承载品牌身份或唯一证据则保留。

## 何时给用户看

取材时内部使用 contact sheet，只向用户提出会改变内容的高影响歧义。完整逐页稿在工作台里就地显示正文引用的图，可点开放大；对图提反馈让模型重画，正文引用路径不变。

## 进文档的方式

图只以文件形式进入 `.planners/by-page.md`：`![说明](相对路径)`。正文引用决定用哪张图、放在哪；同名 `by-page.assets.json`（`doc-assets/1`）是派生索引，只记录文件当前字节与绑定的块锚点，由工作台打开时按正文重建。

素材层面的取舍、处理与视觉检查仍记在素材清单（`asset-manifest/1.1.0`）或项目记忆；`doc-assets/1` 不记录这些判断，避免把没有的元数据写成事实。

## 处理层级

### 保守处理（默认）

- 内容 Hash 去重但保留来源关系；
- 纠正方向和不稳定色彩配置；
- 转成下游稳定支持的 PNG/JPEG/WebP（示意图除外，见下节）；
- 生成审阅预览；
- 检查像素、长宽比、透明背景和清晰度；
- 只去除确定无意义的外部空白。

### 示意图不是照片

由文字确定性渲染出的 SVG 图（见 `references/diagram-lifecycle.md`）**不走位图处理链**：不要转成 PNG/JPEG/WebP，不要重采样或"增强"，也不要生成处理副本。它的源在 `diagram-manifest.json` 里，改图就是改源再重渲染，不生成处理副本。

视觉检查照做：采用前必须真的看过渲染结果——文字可读、不溢出、不重叠、关系方向正确、与正文一致；没看过就保持 `pending`。

### 增强处理（按特定图片批准）

- 从页面截图裁出有效图表或照片；
- 拆分组合图；
- 改善扫描图对比度或文字可读性；
- 为透明素材生成仅供审阅的背景预览。

处理图必须记录处理说明和独立 `processed_sha256`，永不覆盖原图。不得默认生成式补图、去水印、改写数据图表或改变证据内容。

## 内容视觉检查

采用或备用图片在终审前必须确认：目标对象正确、主体完整、无误重复、文字可读、处理没有改变证据。把结果写入素材清单的视觉检查字段或项目记忆；`doc-assets/1` 只保证文件字节，不替你声明看过图。尺寸、坐标、墨迹密度和 OCR 只能辅助定位，不能单独把内容检查标记为通过；模型不能直接看图时交给用户确认。

降级顺序：当前模型原生视觉 → 环境已配置的图像/vision 工具 → 工作台里的用户确认。不在 Skill 中绑定特定商业模型、私有代理或用户密钥路径；前两项都不可用时，保持 `pending` 而不是伪造 `passed`。

## 下游边界

Planners Bypage 决定图片是否与哪页相关；`planners-ppt-hell` 决定最终是否上屏、槽位、`contain|cover`、裁剪比例与锚点。前置处理应尽量保留最大信息。
